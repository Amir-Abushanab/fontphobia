# Evidence (docs only)

The Hugo binary isn't installed and wasn't installed for this spike. Latest release: `curl https://api.github.com/repos/gohugoio/hugo/releases/latest` → `v0.169.0`, published 2026-10-27T16:24:46Z.

What the docs say:

- Directory structure: <https://gohugo.io/getting-started/directory-structure/>. The skeleton is `archetypes/ assets/ content/ data/ i18n/ layouts/ static/ themes/` + `hugo.toml`, with an optional `config/_default/hugo.toml`. The `public` directory holds "the published website" from `hugo build`/`hugo server`. `resources/` caches pipeline output.
- Server: <https://gohugo.io/commands/hugo_server/>. "`-p, --port int` port on which the server will listen (default 1313)", "`--bind string` interface to which the server will bind (default "127.0.0.1")", "`-M, --renderToMemory` render to memory", and it is described as "a webserver with limited options". There's no production mode.
- URLs: <https://gohugo.io/content-management/urls/>. `content/posts/post-1.md → https://example.org/posts/post-1/`. Ugly URLs are opt-in (`uglyURLs`).
- Sitemap: <https://gohugo.io/templates/sitemap/>. Generated by default "in the root of the `public` directory"; disable with `disableKinds = ['sitemap']`; multilingual sites get a sitemapindex.
- Templates: <https://gohugo.io/templates/new-templatesystem-overview/>. In v0.146.0, "The `layouts/partials` directory is renamed to `layouts/_partials`"; base template `layouts/baseof.html`.
- Hugo Pipes: <https://gohugo.io/hugo-pipes/introduction/>. Assets come from `assets/` (or anything mounted there) via `resources.Get`, and are published on `.RelPermalink`/`.Permalink`/`.Publish`.
- `css.Build`: <https://gohugo.io/functions/css/build/>. Added in v0.158.0, "backed by the evanw/esbuild package". Bare `@import "pkg"` resolves through `package.json` `mainFields` (default `["style","main"]`), with reads limited by `security.node.permissions.allowRead` (project dir incl. node_modules). Loaders: `.css` → `css`, everything else → `file` (copies and rewrites the URL), or `dataurl` to inline. `.Data.Artifacts` (v0.165.0) lists copied files with `MediaType`/`RelPermalink`.
- Fingerprint: <https://gohugo.io/functions/resources/fingerprint/>. `js/main.js` → `/js/main.62e...df1.js`, sha256 by default (md5/sha384/sha512 optional), plus an `integrity="sha256-…"` attribute.
- `hugo list all`: <https://gohugo.io/commands/hugo_list_all/>. "List all content including draft, future, and expired." The command page doesn't document the output format; from memory it's CSV with `path,slug,title,date,expiryDate,publishDate,draft,permalink,kind,section` columns, which I couldn't verify here.

The fixture in this dir is **untested**: `hugo.toml`, `layouts/{baseof,home,page,section}.html`, `layouts/_partials/head.html` (Fraunces `<link>` + `css.Build | fingerprint` of `assets/main.css`, which `@import`s fontsource), `content/about.md`, `content/posts/{1,2}.md`, and `package.json` with `@fontsource-variable/inter` (not installed).

# Surprises / gotchas

- Hugo now has a real CSS bundler (`css.Build`, esbuild, v0.158+) that can pull fontsource from node_modules and copy its woff2. Output names and paths for copied fonts aren't documented, so this needs testing with the binary.
- Raw HTML in Markdown is dropped unless `markup.goldmark.renderer.unsafe = true` (set in the fixture).
- `layouts/partials` → `layouts/_partials` (v0.146). Older themes still use `partials`. The overview says the old layout is still largely supported, which I could not verify, so head lookup should check both.
- `hugo server` binds to 127.0.0.1 only and is dev-oriented. Crawl `public/` with a static server.
