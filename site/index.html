One font, three files

Core holds the characters your pages use. Extended holds the Latin letters none of them use yet. Rest holds everything else in the font. The browser loads core first, then another file only when text needs it.

A character that few pages use could go in core or in extended. fontphobia measures both and keeps the one where your pages download less in total.

How it's measured and checked

Cold-cache visits at 390 px and 2× density, with every photo loaded. Sizes count response bodies: HTML, CSS, JavaScript, photos and fonts. They exclude headers and gzip savings on text.

Only the fonts change. The baseline self-hosts full Inter and Google's Latin Fraunces. Sites already using language subsets may save less.

Font verification passed 32 comparisons. Separate checks of the published copies cover all four pages at 390 and 1280 px, at 1× and 2× density, plus a filtered menu.

Text pixels matched within one RGB level per channel. Photos have identical bytes, positions and sizes; they are masked for pixel checks because Chrome can resample the same JPEG differently. The text tolerance covers colour noise also seen with unchanged fonts. Strict and unmasked counts are in the raw results.

Run it on your site

You'll need Node.js 22+ and Google Chrome. In your project folder:

your project
pnpm dlx fontphobia

Review the plan, approve the edits, then see the rendering check.

What the command does
  1. Audit. Open each page in Chrome and record its text and font settings.
  2. Plan. Split each font into core, extended and rest. Repair words that lose kerning.
  3. Build. Write WOFF2 files and update the CSS. Keep axes, hinting and font features.
  4. Verify. Compare the original and optimized pages in Chrome.

Add fontphobia check to your build to catch new text and stale files.

Subset on every build instead

fontphobia auto subsets a built site inside its output folder. It edits no source file and leaves nothing to commit, so there is no check to run.

after your build
pnpm build && pnpm dlx fontphobia auto
  • No browser by default. It reads the text of the built pages. Every run checks that the new files decode, match their sources and shape each word the same, and puts the output back if a check fails.
  • --crawl measures each font in Chrome and writes the same files as the full workflow.
  • --verify adds the pixel comparison in Chrome. Run it when you adopt auto mode or change a font.

The framework integrations take auto: true to do this at the end of each build. Auto mode needs prerendered pages and leaves fonts served by Google or Adobe alone.

Supported font sources

fontphobia edits fonts where they are declared:

SourceWhat fontphobia does
Your own @font-face rules in CSS, Sass, Less, or <style> in Vue, Svelte and AstroCore, extended and rest, in place
Fontsource packagesCopies the package CSS into your project and subsets each slice a page uses
Google Fonts links and next/font/googleReports unused weights; with self-host or eject, serves the exact files Google sent from your site, split
Astro Fonts APIPreloads only the faces pages use; with eject, serves them from your site, split
@nuxt/fontsReports unused weights and families loaded twice; with eject, splits them
next/font/localOne subset file per face
Adobe FontsNever touches Adobe's files; apply-kit removes kit styles nothing uses

Fonts need a recognised open licence, such as OFL or Apache 2.0. Reserved Font Names are renamed inside the files; your CSS family names stay the same.
