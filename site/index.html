Why split a font?

Inter's variable font covers 2,852 characters. The bakery site below uses 68 of them, but each page downloads the full 341 KB file.

A subset keeps fewer characters in a smaller file. There are a few things to watch for:

  • Text added later with characters outside the subset, such as é or €, renders in a fallback font.
  • Words whose letters are split across two files lose kerning, because the browser shapes each file's run separately.
  • Narrowing a variable font's axes or removing its hinting changes glyph widths slightly, which can rewrap a line.
  • New content can make a subset out of date.

fontphobia keeps the unused characters in a separate file, repairs shaping where a split changes it, and compares the pages in Chrome. Options that can change rendering are off by default.

How it works

Run pnpm dlx fontphobia in your project. It audits the site, shows the proposed edits, asks before writing, and verifies the result. Add check to your build to catch later changes.

AuditChrome opens every page and records what each font draws.usage.json
PlanEach font is split into core, extended and rest.no browser
BuildHarfBuzz writes the files and the CSS is edited in place.manifest.json
VerifyEach page is rendered with the old fonts and the new ones, then compared.diff images
CheckAfter each build, makes sure new text is still covered.postbuild, CI

Walkthrough: Little Levain

Little Levain is a sample bakery site: four HTML pages, two fonts, no framework. The output below is from a run of fontphobia 0.2.0.

  • Inter for body text, the full variable WOFF2 (341 KB).
  • Fraunces for headings, Google's Latin subset (66 KB).

The source is in examples/bakery.

Both fonts start with a single @font-face rule:

styles.css
@font-face {
  font-family: 'Inter';
  src: url('./fonts/InterVariable.woff2') format('woff2');
  font-weight: 100 900;
  font-style: normal;
  font-display: swap;
}
@font-face {
  font-family: 'Fraunces';
  src: url('./fonts/Fraunces.woff2') format('woff2');
  font-weight: 100 900;
  font-style: normal;
  font-display: swap;
}

1. Audit

The audit serves the built site locally and opens its pages in Chrome. It reads text after CSS is applied, including generated content, list markers and text transforms. For each font it records:

  • the characters the face draws, per page;
  • the OpenType features in use (the menu's prices use tabular figures, tnum);
  • the variable axis values in use, such as weight and optical size;
  • every word, so the plan can check shaping later.

It visits four viewport widths to catch responsive content, and a range of browser font sizes to catch optical-size changes.

2. Plan

The plan uses the audit to divide each font into three files:

Core

Characters used on at least half the pages that use the face. Loads wherever the original did.

Extended

Every other character any page uses. Only loads on pages that need one of them.

Rest

Everything else in the original font, so characters added later still render in it. Rarely loads.

Together they cover the original character set. CSS unicode-range rules tell the browser which file to use for each character. A page with new characters can load an extra file rather than fall back to another font.

Shaping repair

A browser shapes text one font file at a time. Split a word across files and it can lose kerning or ligatures at the boundary.

fontphobia checks each recorded word with HarfBuzz, using the original font and the proposed split. If they differ, it moves the word's characters into core and checks again. Four characters moved on this site, adding 480 bytes.

--allow split-shaping skips the repair. Here that saves 480 bytes and loses kerning in four words.

Opt-ins

The plan also measures options that can change rendering. For Little Levain:

Opt-inSavesWhat changes
limit-axes41.2 KBNarrows the variable axes to the ranges in use. Glyph widths shift by up to ~0.02%.
drop-hint-refs16.6 KBDrops the reference characters FreeType's auto-hinter uses, so extended characters hint differently on Linux and ChromeOS.
split-shaping480 BSkips the shaping repair; four words lose kerning where files meet.
drop-hinting248 BRemoves TrueType hinting, which changes rasterization on Windows and layout on Linux at 1×.

Pass --allow with an option's name to use it. The failed verification below shows the result of limit-axes.

3. Build

With --write, or after you confirm the prompt, HarfBuzz writes the six files as WOFF2 next to the originals. It keeps everything that affects rendering:

  • glyph names, because dropping them changes how Chrome on macOS rasterizes text;
  • TrueType hinting, and the .notdef outline;
  • every OpenType feature CSS can turn on;
  • the full variable axes.

File names include a content hash, so they can be cached indefinitely. The CSS is edited in place: each original @font-face becomes a marked block of three rules with the same descriptors.

git diff styles.css (Inter's block; the rest file's 1,900-character range is shortened)
-@font-face {
-  font-family: 'Inter';
-  src: url('./fonts/InterVariable.woff2') format('woff2');
-  font-weight: 100 900;
-  font-style: normal;
-  font-display: swap;
-}
+/* fontphobia:begin inter-100-900-normal 0.2.0 (generated; rerun `fontphobia build`) */
+@font-face {
+  font-family: 'Inter';
+  src: url('./fonts/InterVariable.rest.5172829c.woff2') format('woff2');
+  font-weight: 100 900;
+  font-style: normal;
+  font-display: swap;
+  unicode-range: U+180-1C3, U+1C5-254, U+256-27B, … U+1F850, U+1F852;
+}
+@font-face {
+  font-family: 'Inter';
+  src: url('./fonts/InterVariable.ext.4b044342.woff2') format('woff2');
+  font-weight: 100 900;
+  font-style: normal;
+  font-display: swap;
+  unicode-range: U+A1-AC, U+AE-AF, U+B1-B6, U+B8-E1, U+E3-E7, U+EA-148, U+14A-17F, U+300-304, U+306, U+308, U+30A, U+327, U+2011, U+2020-2021, U+2030, U+2032-2033, U+20AC, U+2212;
+}
+@font-face {
+  font-family: 'Inter';
+  src: url('./fonts/InterVariable.core.86af9d32.woff2') format('woff2');
+  font-weight: 100 900;
+  font-style: normal;
+  font-display: swap;
+}
+/* fontphobia:end inter-100-900-normal */

Core has no unicode-range, so it covers everything the other two don't and loads wherever the original did. The extended file's range includes whole blocks around the characters in use, such as Latin-1 and Latin Extended-A, so an ø or č added later doesn't need a rebuild.

4. Verify

verify checks the result three ways, cheapest first:

  1. Files and CSS. Every output is decoded and validated, its bytes are checked against the manifest, and the CSS is checked to load it with the original descriptors.
  2. Shaping. Every recorded word is shaped with HarfBuzz from the original font and from the split files, at every axis value in use. Glyphs, advances and positions have to match exactly.
  3. The browser. Every page is loaded twice in Chrome, once as built and once with the original fonts swapped back in, at every width and at 1× and 2× pixel density. Text box layouts and pixels are compared.

5. Check

fontphobia check reads the fonts, CSS and built content without a browser or network access. It reports changed files, missing features and characters that need the rest file.

Add a journal post mentioning smørrebrød, Nørrebro and ψωμί, and it reports:

~/little-levain
pnpm dlx fontphobia check
fontphobia: the site renders as built, but this downloads more than it should:
  - Inter: ί (U+03AF), μ (U+03BC), ψ (U+03C8), ω (U+03C9) would load the rest file (in journal/copenhagen.html)
Run: npx fontphobia@0.2.0 --write

The ø is already in extended. The Greek letters need the 309 KB rest file, so they still render in Inter, but the page downloads more. This is a warning; --strict makes it fail the check.

check can run after every build through the integrations for Astro, Nuxt, Next.js, Vite, VitePress, Docusaurus, Eleventy, React Router, Rsbuild, Rspack and webpack, or a "postbuild": "fontphobia check" script in package.json. For content from a CMS that isn't in the repository, fontphobia check --url https://example.com crawls the live site, for example on a schedule.

6. Revert

~/little-levain
pnpm dlx fontphobia revert

The original @font-face rules are restored byte for byte, and the generated files and manifest are deleted.

Other font sources

Little Levain declares its fonts in a stylesheet. fontphobia also handles the sources below, and edits each face where it's declared:

SourceWhat fontphobia does
Your own @font-face rules in CSS, Sass, Less, or <style> in Vue, Svelte and AstroCore, extended and rest, in place
Fontsource packagesCopies the package CSS into your project and subsets each slice a page uses
Google Fonts links and next/font/googleReports unused weights; with self-host or eject, serves the exact files Google sent from your site, split
Astro Fonts APIPreloads only the faces pages use; with eject, serves them from your site, split
@nuxt/fontsReports unused weights and families loaded twice; with eject, splits them
next/font/localOne subset file per face
Adobe FontsNever touches Adobe's files; apply-kit removes kit styles nothing uses

fontphobia only modifies fonts under a recognised open licence, such as the SIL Open Font License or Apache 2.0. For fonts with a Reserved Font Name, the subset files are renamed internally as the OFL requires; the CSS font-family doesn't change.

Run it on your site

You'll need Node.js 22+ and Google Chrome. Run this in your project folder to see the proposed changes:

your project
pnpm dlx fontphobia
